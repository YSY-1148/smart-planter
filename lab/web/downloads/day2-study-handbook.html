风扇为什么会转？

分清输入、判断、输出这三件事。

先想一个简单场景：屋里热了，你看一眼温度，再决定开风扇。单片机也要走完这几步，只是把规则写成程序。

温度：现在多少度 → 规则：需要开风扇吗 → 输出：发出开关信号

认识概念

输入：程序得到的信息，例如温度。

输出：程序发出的控制信号，例如要求风扇开启。

这一课先用“达到 28°C 就开”的单阈值示例。真实项目还会保留历史状态、检查数据是否有效；等你理解这条链路，再到专题 18 学滞回。

做一个小实验

先把温度设为 25°C，点一次“执行判断”；再设为 30°C，观察判断前后有什么变化。

改变输入只是在提供新条件；点击执行，才让这段教学规则处理条件。 交互实验在本地学习页运行；本手册用于阅读。

先读懂一条 C 语句

认识变量、赋值和比较，不用一次看完整个函数。

程序要先把一个数存起来，才能拿它判断。你可以把变量想成带名字的格子：“temperature”这个格子里现在放着 25。

读右边的值 → 存入左边变量 → 用变量做判断

认识概念

变量：有名字的一块存储，用来保存数值。

赋值 =：把右边的结果存入左边。

比较 >=：判断左边是否大于或等于右边，得到真或假。

本项目温度使用十分之一摄氏度：temp10=280 表示 28.0°C。先理解普通整数，之后看到 280 就知道它不是 280°C。

做一个小实验

声明一个整数变量，并把它的初值设成 25。

程序怎样控制一根引脚？

理解 GPIO 输出与风扇真正转动之间的关系。

程序里的 fan=1 只是一个数。单片机还要把某个引脚设成高电平，让驱动电路接通风扇的供电通路。

输出意图 fan=1 → PD12 输出高电平 → 驱动通路完整，风扇转动

认识概念

GPIO：可以由程序配置为输入或输出等用途的通用引脚。

高 / 低电平：引脚上的两类电压状态，在合适的数字电路中表示 1 / 0。

驱动电路：接收控制信号，并为负载开关较大的电流。

项目使用 PD12 控制风扇驱动。这里演示高电平有效的通路；真实 GPIO 的输出能力有限，不能把风扇直接当小电流指示灯接在引脚上。

做一个小实验

先开启控制信号，再断开驱动信号线。比较“引脚电平”和“风扇动作”。最后恢复接线。

引脚为高电平，只说明控制信号已发出；负载动作还取决于连接和供电。 交互实验在本地学习页运行；本手册用于阅读。

逐句读代码

教学伪代码 · 原项目的对应操作位于 board.c / board_outputs

fan_requested = 1;

先保存“要求开风扇”的意图。它还只是程序中的一个数。

write_fan_pin(fan_requested);

调用一个教学命名的函数，把引脚设为对应电平。函数名像操作名称，括号内是交给它的数据；原项目实际使用 HAL_GPIO_WritePin。

入门 4 / 12

程序怎样知道缺水了？

分清引脚电平和“缺水”这个业务含义。

输入引脚用来读外部状态。程序读到的先是高或低，之后才根据接线约定，把这个电平解释成“低液位”或“正常液位”。

液位开关状态 → PB1 上的电平 → 程序解释为缺水 / 正常

认识概念

输入：读取外部电路给引脚的电平。

上拉：把没有被外部拉低的信号偏向高电平；能否可靠建立电平还取决于电路。

当前代码读取 PB1，高电平返回 true，表示低液位；输入配置了上拉。断线也可能表现成高电平，所以当前单个开关不能可靠区分缺水和断线。

做一个小实验

分别观察“开关拉低”和“开关释放”；再模拟断线，看程序能否仅凭电平分辨断线与缺水。

此模型假设上拉有效、电路理想；它解释的是逻辑关系。 交互实验在本地学习页运行；本手册用于阅读。

逐句读代码

教学伪代码 · 对应 board.c / board_water_low 的读取与比较

level = read_PB1();

调用教学命名的读取函数，把返回的电平存进 level。括号为空表示这里没有交给函数额外参数。

water_low = (level == HIGH);

HIGH 代表高电平。== 检查是否相等，然后把比较结果存入 water_low：真表示低液位，假表示正常。

自己说一遍

当前接法下，PB1 读到高电平，程序能可靠判断是缺水还是断线吗？

  • 能，高电平只可能是缺水

  • 能，因为函数返回 bool
回答后核对

对。更多诊断能力需要额外硬件或信息，函数名不会增加诊断信息。

正确选项：不能，这两种情况可能给出相同电平

入门 5 / 12

时钟是怎么给计数器打拍子的？

分清频率、分频和一次计数需要的时间。

把时钟想成连续的节拍。1 MHz 表示每秒一百万拍；计数器每拍加一时，两次计数之间就是 1 微秒。

TIM4 输入 84 MHz → PSC=83，除以 84 → 计数频率 1 MHz

认识概念

Hz / MHz：每秒的节拍数；1 MHz 等于 1,000,000 Hz。

分频：让输出节拍比输入更慢。

周期：一个节拍的时间，等于 1 除以频率。

本项目 CPU 配置为 168 MHz，APB1 为 42 MHz，TIM4 为 84 MHz。它们属于不同的时钟位置；不要拿 CPU 主频直接代替定时器时钟。完整时钟树留到专题 29–36。

做一个小实验

输入时钟固定为 84 MHz。把 PSC 依次设成 83 和 167，观察计数频率与每次计数时间。

这里硬件使用 PSC+1 作为除数；PSC=83 就是除以 84。 交互实验在本地学习页运行；本手册用于阅读。

逐句读代码

教学计算 · 对应项目的 TIM4 配置

counter_hz = timer_hz / (PSC + 1);

先计算计数器的节拍数。84,000,000 ÷ 84 = 1,000,000。

tick_seconds = 1.0 / counter_hz;

一拍的秒数是频率的倒数。1 ÷ 1,000,000 秒就是 1 微秒。

自己说一遍

84 MHz 输入，PSC=83，计数器的频率是多少？

  • 84 MHz
  • 1 MHz
  • 83 MHz
回答后核对

对。84 MHz 除以 (83+1)，得到 1 MHz。

正确选项：1 MHz

解释为什么本项目 CPU 是 168 MHz，却用 84 MHz 计算 TIM4。

入门 6 / 12

一根引脚怎样调节补光？

分别说清 PWM 的频率和占空比。

PWM 让引脚周期性地高、低切换。每个周期有多长决定频率；每个周期中有多大比例为高，决定占空比。负载效果还取决于驱动和灯具。

1 MHz 计数节拍 → 0 到 999：一个周期 → CCR=250：25% 高电平

认识概念

PWM：按周期输出脉冲，并调整有效电平持续的比例。

ARR：计数上限；从 0 数到 ARR，一共 ARR+1 个计数。

CCR：比较值；本例 PWM1、向上计数、高有效时决定高电平宽度。

当前 TIM4：PSC=83，ARR=999，周期为 1000 微秒，即 1 kHz。项目把 0–100 的补光百分比乘 10 写入 CCR。

做一个小实验

把占空比依次设为 0%、25%、50%、100%。观察高电平宽度变化，确认频率设置没有跟着改变。

0% 和 100% 是恒低、恒高的极限情况，此时引脚没有周期性边沿；定时器周期配置仍是 1 ms。 交互实验在本地学习页运行；本手册用于阅读。

逐句读代码

教学伪代码 · 对应 board_outputs 中的 PWM 比较值更新

duty_percent = 25;

先设定想要的占空比百分数。

compare_value = duty_percent * 10;

把 25 换算成 250 个计数。因为一个周期是 1000 个计数，1% 对应 10 个。

set_pwm_compare(compare_value);

将比较值交给定时器。这里是教学命名；原项目用 __HAL_TIM_SET_COMPARE 更新 CCR。

自己说一遍

保持 PSC、ARR 不变，把 CCR 从 250 改成 500，主要改变什么？

  • 占空比从 25% 变成 50%
  • 定时器频率翻倍
  • CPU 主频翻倍
回答后核对

对。周期仍为 1000 个计数，高电平宽度从 250 个变成 500 个。

正确选项：占空比从 25% 变成 50%

用一句话分别解释“1 kHz”和“25%”，并写出 CCR 的计算。

入门 7 / 12

怎样把电压变成数字？

知道 ADC 的输入、输出及其与物理量的区别。

数字输入只区分高低。有时我们需要知道电压具体多大，就使用 ADC，把一定范围内的模拟电压转换成整数。

输入 1.65 V → ADC 按量程量化 → 得到约 2048

认识概念

ADC：模数转换器：把模拟电压转换成数字编码。

12 位：有 4096 种编码，编号从 0 到 4095。

参考电压：确定转换量程的参考，本练习设为 3.3 V。

这是扩展教学。原种菜机用 DHT11 和 BH1750 数字传感器，没有配置 ADC 来采集土壤湿度。ADC 编码还需要传感器关系和标定，才能换算成物理量。

做一个小实验

依次设 0、1.65、3.3 V。记下编码，再想一想：2048 这个数是否天然等于湿度 50%？

使用理想量化约定：floor(Vin / 3.3 × 4096)，并限制到 0–4095。没有加入电气误差和噪声。 交互实验在本地学习页运行；本手册用于阅读。

逐句读代码

教学伪代码 · 原固件未实现此 ADC 链路

code = floor(voltage / 3.3 * 4096);

按理想量程把电压变成编码。floor 表示向下取整。

code = clamp(code, 0, 4095);

clamp 表示限幅。满量程时也不能超出 12 位的最大码 4095。

自己说一遍

一个 12 位 ADC 的最大无符号编码是多少？

  • 4096
  • 4095
  • 12
回答后核对

对。0 到 4095 一共有 4096 个不同的数。

正确选项：4095

说明 ADC 编码为什么还不能直接当成温度或湿度。

入门 8 / 12

项目的温湿度是怎样读出来的？

知道数字传感器也需要通信和有效性检查。

DHT11 已经把测量结果编成一串位，单片机通过一根数据线读它。这里要读的是脉冲的时间长短，再组装成温湿度数据。

测量一位的高脉宽 → 把各位组装成字节 → 检查整帧，再接受温湿度

认识概念

位 bit：只有 0 或 1 的一份信息。

脉宽：电平持续的一段时间。

校验：检查收到的数据是否符合约定，用来发现一部分错误。

当前项目读取 40 位，高脉宽严格大于 45 微秒时把该位记为 1；之后还要检查五字节的和及数值范围。单个位能判定，不代表整帧有效。

做一个小实验

把高脉宽依次设成 45 和 46 微秒；再设为“整帧校验失败”，观察是否仍应接受测量。

这是脉宽判位和整帧接受条件的简化教学，不模拟 DHT 的完整时序、超时或电气连接。 交互实验在本地学习页运行；本手册用于阅读。

逐句读代码

适用条件：固定采样率、连续批量处理。

先预测：DMA 能否保证任务永远读到原来的那一批？

故障验证

处理一半缓冲超过其复用期限
